1. 产品概述
================================================================================

产品名称：PixelBeads 拼豆图纸制作小助手
核心定位：帮助拼豆（Perler Beads）爱好者将任意图片快速转化为可执行的拼豆图纸，
          并提供库存管理、AI 调色优化、历史记录等配套功能。

目标用户：拼豆手工爱好者，尤其是有一定色彩库存但缺乏图纸制作工具的用户。

核心价值：
  - 一键图片像素化 → 图纸生成（10秒内）
  - 对接个人豆子库存，精确计算用量 & 库存差缺
  - AI 调色建议（Qwen VL），5种风格可选
  - 历史作品管理，支持库存回滚
  - 全平台可用（PC + 移动端响应式布局）

产品 URL：部署于 Sealos 云平台，端口 3000
Docker Hub：lajones/pixelbeads（最新：v29）

2. 技术栈 & 架构总览
================================================================================

┌──────────────────────────────────────────────────────────────┐
│                       用户浏览器                              │
│  HTML/CSS/JS（Bootstrap 5.3 + 原生 ES6）                     │
│  GA4（流量分析）  +  自建埋点（/api/events）                  │
└──────────────────┬───────────────────────────────────────────┘
                   │ HTTP / REST API
┌──────────────────▼───────────────────────────────────────────┐
│                  Node.js + Express 后端                       │
│  server.js（所有 API）  |  db.js（MySQL 连接池）              │
└──────────────────┬───────────────────────────────────────────┘
                   │ mysql2/promise
┌──────────────────▼───────────────────────────────────────────┐
│                  MySQL 数据库                                  │
│  users / inventory / history / events                        │
└──────────────────────────────────────────────────────────────┘
                   │ DashScope HTTP API
┌──────────────────▼───────────────────────────────────────────┐
│         阿里云通义千问 Qwen VL Plus（AI 调色）                │
└──────────────────────────────────────────────────────────────┘

前端：纯原生 HTML + JavaScript + Bootstrap 5.3，无框架依赖
后端：Node.js (Express)，RESTful API
数据库：MySQL 8.x
AI 模型：Qwen VL Plus（DashScope OpenAI 兼容接口）
分析：Google Analytics 4（GA4）+ 自建事件表
部署：Docker 容器化，Sealos 云平台托管
图像处理：PixelIt 库（像素化核心算法）
导出：PapaParse（CSV）

┌─────────────────┬──────────────┬──────────────────────────────┐

5. 后端 API 接口列表
================================================================================

认证类
  POST /api/auth/register    注册新用户
    Body: { username, password }
    Return: { id, username }

  POST /api/auth/login       用户登录
    Body: { username, password }
    Return: { id, username, avatar }

  POST /api/user/profile     更新头像
    Body: { userId, avatar }

库存类
  GET  /api/inventory/:userId      获取用户库存列表
  POST /api/inventory/:userId      全量保存库存（upsert + 删除不在列表中的）

历史记录类
  GET    /api/history/:userId      获取历史记录（最近50条）
  POST   /api/history/:userId      新增历史记录
  DELETE /api/history/:id          删除历史记录

AI 调色
  POST /api/ai/colorize
    Body: { imageBase64, originalImageBase64, colors, style }
    style 枚举: simple | standard | detailed | cartoon | gradient
    Return: { replacements: {"#OLD": "#NEW", ...} }

数据埋点
  POST /api/events
    Body: { event, userId, properties }

管理后台
  GET  /api/admin/stats?pwd=<密码>
    Return: { users, events, daily_events, daily_users }

静态文件
  GET  /            → docs/index.html（主应用）
  GET  /admin.html  → docs/admin.html（数据后台）

6. 前端模块说明
================================================================================

■ main.js（核心，约 1300 行）
  - 认证流程（登录/注册，含确认密码校验）
  - 步骤管理（activateStep，4步骤向导 + 进度条动画）
  - 抽屉管理（库存/历史 Drawer 开关）
  - 图片上传 & 预览（拖拽 + 点击，FileReader）
  - 图纸生成（调用 PixelIt，配置尺寸/色板）
  - 手工编辑模式（鼠标点击/右键修改像素颜色）
  - 放大镜（浮窗/底部浮层，支持拖拽 & 触控，逐块遍历）
  - AI 调色（调用后端 /api/ai/colorize，5风格，左右对比预览）
  - 用量统计表（珠子颜色 & 数量 & 库存状态）
  - 完成拼豆（扣库存 + 保存历史）
  - 历史记录渲染（含删除 & 库存回滚）
  - 数据埋点（track() 函数，同步上报 GA4 + 自建后端）

■ storage.js（数据持久化层）
  - localStorage（离线缓存）+ API（云端同步）双层架构
  - 用户登录态、库存、历史均通过此层读写
  - login / register / logout / getInventory / saveInventory
  - addHistory / deleteHistory / restoreStockFromHistory

■ pixelit.js（像素化引擎，基于第三方库定制）
  - pixelate()：图片像素化主函数
  - setPalette()：设置目标色板
  - drawGrid()：渲染像素网格（含坐标标签）
  - updatePixel()：单像素更新（用于手工编辑）
  - getGrid()：获取当前像素网格数据（二维数组）

■ exporter.js（导出模块）
  - generatePrintableCanvas()：生成可打印 PNG（带格子编号）
  - exportGridCSV()：导出图纸像素 CSV
  - exportColorUsageCSV()：导出颜色用量清单 CSV
  - countColors()：统计各颜色像素数量

8. 数据埋点与分析体系
================================================================================

双轨上报架构：
  轨道 A：Google Analytics 4（GA4，ID: G-28V6C6FTW9）
          → 负责：页面 PV/UV、用户地域/设备、会话留存（自动计算）
  轨道 B：自建 events 表
          → 负责：产品漏斗、功能使用率、AI 接受率（精确用户维度）

埋点事件清单：
  user_register          注册成功
  image_uploaded         上传图片完成
  grid_generated         生成图纸  附带: {size, palette}
  ai_colorize_start      点击AI调色 附带: {style}
  ai_colorize_accept     接受AI结果
  ai_colorize_reject     放弃AI结果
  export_png             导出PNG
  complete_bead          点击拼他（扣库存）

运营验收指标（推广后2周目标）：
  注册用户     ≥ 30
  激活率       ≥ 50%（完成生成 / 上传图片）
  PNG 导出     ≥ 20 次
  AI 调色使用率 ≥ 20%（使用过 / 生成过图纸）

查看数据：
  - GA4 Dashboard：https://analytics.google.com

9. 部署方式（Sealos + Docker）
================================================================================

构建镜像：
  docker build -t lajones/pixelbeads:vXX .
  docker push lajones/pixelbeads:vXX

Sealos 更新步骤：
  1. 推送新镜像到 Docker Hub
  2. 在 Sealos 控制台修改镜像版本号 → 重新部署
  3. 数据库表通过 schema.sql IF NOT EXISTS 自动更新（无需手动迁移）

环境变量（需在 Sealos 配置）：
  DB_HOST        MySQL 主机地址
  DB_PORT        端口（默认 3306）
  DB_USER        数据库用户名
  DB_PASSWORD    数据库密码
  DB_NAME        数据库名（默认 pixelbeads）
  QWEN_API_KEY   通义千问 DashScope API Key
  ADMIN_PWD      Admin 后台密码（默认 yangchen1215）

Dockerfile 说明：
  - 基础镜像：m.daocloud.io/docker.io/library/node:18-alpine（国内镜像源）
  - 对外端口：3000
  - 启动命令：node server.js

10. 迭代规划 & 未来方向
================================================================================

近期（高优先级）
  □ 密码加密存储（bcrypt），提升安全性
  □ AI 调色效果优化：
      - 前端算法先去噪（孤立像素检测），再送 AI 调色
      - 考虑改为"AI 给出色板建议，前端执行合并"方案
  □ 推广期数据分析 & 迭代（根据 Admin 后台数据驱动）

中期（功能扩展）
  □ 移动端相机直拍入口（input[capture=camera]）
  □ PWA 可安装（manifest.json + Service Worker）
  □ 文生图功能（通义万象 Qwen 文生图 API → 自动像素化）
  □ 图纸模板库（预设热门图案，一键导入）
  □ 社区分享（作品公开展示，他人参考色板）

长期（产品化方向）
  □ 多色板市场（拼豆品牌官方色板导入，如 Hama/Perler/哈鸟）
  □ 协同拼豆（多人共用同一图纸，独立管理各自库存段）
  □ 成本估算（对接豆子价格库，生成制作成本报告）
  □ AR 预览（手机摄像头叠加图纸，辅助实际拼制）

11. 已知问题 & 技术债务
================================================================================

安全
  [高] 密码明文存储（password_hash 字段实为明文）
       → 待改为 bcrypt 哈希
  [中] 无 JWT/Session 认证，userId 由前端传入，存在伪造风险
       → 待改为服务端 Session 或 JWT Token
  [低] Admin 后台密码为 URL 明文参数
       → 可改为 POST 请求或 HTTP Basic Auth

体验
  [中] AI 调色效果不稳定，存在过度调色问题
       → 提示词策略持续优化中
  [低] 移动端不支持相机直拍（需用户从相册选择）
  [低] 无密码找回功能

工程
  [低] src/ 目录为旧版备份，未清理
  [低] 前端无构建工具，所有逻辑在单文件 main.js（~1300行）
       → 规模扩大后建议引入 Vite + 模块化
